# 产品需求文档

## 1. 项目名称

客户需求提交与后台管理 MVP

## 2. 项目定位

本项目是一个本地运行的客户需求提交与后台管理 MVP 网站，用于让客户提交任务需求、上传参考材料，并让管理员在后台集中查看订单、下载文件、修改处理状态和维护内部备注。

当前实现偏向轻量内部工具，不是正式上线的多用户 SaaS 系统。项目采用 Node.js + Express 提供服务，SQLite 存储订单数据，uploads 文件夹保存客户上传材料，前端使用原生 HTML、CSS 和 JavaScript。

## 3. 项目目标

1. 提供一个稳定、简单的客户需求提交入口。
2. 支持客户上传一个或多个需求相关文件。
3. 支持管理员通过后台查看所有提交记录。
4. 支持管理员查看订单详情、下载上传文件、修改订单状态和内部备注。
5. 保持本地部署和本地测试简单，便于后续快速迭代。
6. 通过文档统一接口、数据库和测试标准，方便多个 Codex 会话协作开发。

## 4. 用户角色

### 4.1 客户

客户是需求提交方，通过 `/submit` 页面填写需求信息并上传材料。客户当前不需要注册或登录，可通过订单号和提交时填写的联系方式在 `/order-query` 查询本人订单的基础处理状态，并可在 `/supplement-upload` 为原订单补充上传资料。

### 4.2 管理员

管理员是后台处理方，通过 `/admin/login` 登录后台。管理员可以查看订单列表、进入订单详情、下载客户上传文件、修改订单状态和维护仅后台可见的内部备注。

当前默认账号密码来自 `config.js`，也可以通过环境变量覆盖：

- 默认账号：admin
- 默认密码：admin123

## 5. 当前 MVP 已实现功能

1. 客户提交需求。
2. 多文件上传。
3. 后台管理员登录。
4. 后台订单列表。
5. 订单详情查看。
6. 上传文件下载。
7. 订单状态修改。
8. 内部备注修改。
9. SQLite 数据库存储。
10. uploads 文件夹保存客户上传材料。
11. 订单编号自动生成，格式为 `DDYYYYMMDDNNN`，例如 `DD20260707001`。
12. 后台未登录访问保护。
13. 客户通过订单号和联系方式查询订单基础状态。
14. 客户通过订单号和联系方式补充上传资料与补充说明。

## 6. 客户端功能说明

### 6.1 访问入口

客户端页面路径为：

- `/submit`
- `/submit-success`
- `/order-query`
- `/supplement-upload`

访问根路径 `/` 时，当前代码会自动跳转到 `/submit`。

### 6.2 提交表单字段

客户提交页当前包含以下字段：

| 字段 | 字段名 | 是否必填 | 当前说明 |
| --- | --- | --- | --- |
| 姓名或昵称 | `customer_name` | 是 | 客户名称、昵称或称呼 |
| 联系方式 | `contact` | 是 | 微信、QQ、手机号或邮箱等 |
| 任务类型 | `task_type` | 是 | 必须为当前配置中的任务类型 |
| 截止时间 | `deadline` | 是 | 前端使用 `datetime-local` 输入 |
| 具体需求 | `requirement` | 是 | 客户的主要需求描述 |
| 附加备注 | `extra_note` | 否 | 客户补充说明 |
| 上传材料 | `materials` | 否 | 支持多文件上传 |

### 6.3 当前任务类型

当前实现中的任务类型来自 `config.js`：

1. 课设报告
2. 实验报告
3. PPT制作
4. 代码作业
5. 论文/文档
6. 其他

### 6.4 文件上传规则

当前支持的扩展名为：

- `.doc`
- `.docx`
- `.pdf`
- `.xls`
- `.xlsx`
- `.ppt`
- `.pptx`
- `.zip`
- `.rar`
- `.png`
- `.jpg`
- `.jpeg`

单个文件最大 100MB。前端会先做扩展名和大小校验，后端也会通过 multer 再次校验。

上传文件会保存到 uploads 目录，服务端使用时间戳加随机字符串重命名，避免覆盖已有文件。数据库会保存原始文件名、存储文件名、文件路径、MIME 类型和文件大小。

### 6.5 提交成功结果

客户提交成功后，会跳转到 `/submit-success?orderNo=订单号`。提交成功详情页展示订单编号、任务类型、联系方式、截止时间、提交时间和当前状态，并提醒客户保存订单号。

### 6.6 客户订单查询

客户可打开 `/order-query`，输入订单号和提交时填写的联系方式查询订单基础状态。

查询结果仅展示客户可见信息：

1. 订单号。
2. 任务类型。
3. 联系方式。
4. 截止时间。
5. 提交时间。
6. 当前状态。
7. 需求摘要。
8. 上传文件数量。

客户订单查询不展示后台内部备注、数据库内部 ID、管理员信息、服务器文件路径或文件下载地址，也不提供客户修改订单基础信息或订单状态的能力。查询成功后页面提供“补充上传资料”入口。

### 6.7 客户补充资料上传

客户可打开 `/supplement-upload`，输入订单号和提交时填写的联系方式，为已有订单补充说明或上传补充资料。

补充上传规则：

1. 必须同时校验订单号和联系方式。
2. 订单不存在或联系方式不匹配时，统一提示未查询到订单。
3. 补充说明和补充文件至少需要提供一个。
4. 补充文件沿用订单提交的上传格式和大小限制。
5. 补充上传成功后，不修改订单原始字段、订单状态或后台内部备注。
6. 客户侧成功结果只展示订单号、补充文件数量、是否填写说明和提交时间，不提供下载地址或服务器文件路径。

## 7. 后台管理端功能说明

### 7.1 登录

后台登录页面路径为：

- `/admin/login`

登录成功后前端跳转到 `/admin`。如果已经登录，再访问 `/admin/login` 会跳转到 `/admin`。

### 7.2 订单列表

后台订单列表页面路径为：

- `/admin`

当前列表展示字段：

1. 订单编号
2. 客户姓名
3. 联系方式
4. 任务类型
5. 截止时间
6. 状态
7. 提交时间
8. 操作入口

列表数据由 `/api/admin/orders` 获取，按提交时间倒序和订单 id 倒序排列，最新订单靠前。

### 7.3 订单详情

订单详情页面路径为：

- `/admin/orders/:id`

详情页当前展示：

1. 订单编号
2. 客户姓名
3. 联系方式
4. 任务类型
5. 截止时间
6. 提交时间
7. 具体需求
8. 附加备注
9. 上传文件列表
10. 当前状态
11. 内部备注
12. 客户补充资料和补充说明

详情数据由 `/api/admin/orders/:id` 获取。

### 7.4 文件下载

管理员可以在订单详情页点击文件链接下载上传材料。下载接口为：

- `/admin/files/:id/download`

该路径需要管理员登录。下载时服务端会根据数据库中的 `stored_name` 找到本地文件，并尽量使用 `original_name` 作为下载文件名。

### 7.5 状态与内部备注

管理员可以在详情页修改订单状态和内部备注。当前状态枚举为：

1. 未处理
2. 处理中
3. 已完成
4. 已取消

内部备注仅后台可见，不会展示给客户。

## 8. 当前版本不包含的功能

当前 MVP 不包含以下功能：

1. 客户注册登录。
2. 客户可见处理进度备注。
3. 在线支付。
4. 聊天系统。
5. 多管理员和复杂权限管理。
6. 管理员密码加密存储。
7. 邮件、短信或微信通知。
8. 文件在线预览。
9. 文件删除、文件分类或补充文件管理。
10. 数据统计和导出。
11. AI 自动处理需求。
12. 正式生产部署、安全加固和备份体系。

## 9. 后续可迭代功能

建议后续迭代方向：

1. V1.2.3 客户补充资料上传已实现待验收：客户通过订单号和联系方式验证订单后，为原订单补充上传资料并填写补充说明，后台可查看补充资料和补充说明。
2. 客户可见进度备注暂缓，不作为当前下一版本目标，可作为后续可选优化。
3. 图片和 PDF 在线预览。
4. 文件删除、补充文件管理和文件分类。
5. 今日订单数、本周订单数、未处理订单统计和即将截止订单统计。
6. CSV 或 Excel 导出。
7. 管理员密码加密、环境变量完善、数据库备份、文件备份、日志管理和安全检查。
