# 后续开发计划

## 1. 文档目的

本文档用于统一后续开发节奏和优先级。后续 Codex 开发会话应先阅读本文档，再结合 `PRODUCT_REQUIREMENTS.md`、`API_CONTRACT.md` 和 `DB_SCHEMA.md` 判断是否可以实施。

## 2. 总体原则

1. 当前阶段优先保证原有功能稳定。
2. 不要为了单个新功能大改项目结构。
3. 不要在未更新文档的情况下改变路由、接口字段或数据库结构。
4. 后台增强优先级高于复杂客户体系。
5. 每次开发后必须按 `TEST_CHECKLIST.md` 做回归测试。

## 3. V1.0 MVP，已完成

当前版本已经完成：

1. 客户提交需求。
2. 多文件上传。
3. 后台登录。
4. 订单列表。
5. 订单详情。
6. 文件下载。
7. 状态修改。
8. 内部备注。
9. SQLite 数据库存储。
10. uploads 本地文件保存。

## 4. V1.1 后台管理增强，已实现

已完成后台管理效率增强：

1. 后台搜索。
2. 状态筛选。
3. 任务类型筛选。
4. 分页。
5. 排序。
6. 状态颜色标签。
7. 截止时间提醒。

当前实现沿用原有 HTML 页面 + fetch JSON 接口结构，不修改数据库表结构。列表查询通过 `/admin` query 参数驱动，并由 `/api/admin/orders` 返回当前页数据、总数、分页信息、筛选条件和排序条件。

V1.1 开发注意事项：

1. 筛选、分页和排序不要破坏默认“最新订单靠前”的行为。
2. 状态颜色标签应与现有状态枚举保持一致。
3. 截止时间提醒只用于后台列表展示，不改变订单状态字段。

## 5. V1.2 客户体验增强

建议在后台基础能力稳定后，再增强客户体验：

1. 提交成功详情页。（V1.2.1 已实现，待测试验收）
2. 客户订单查询。（V1.2.2 已实现，待测试验收）
3. 客户可见进度备注。
4. 客户补充资料。

### 5.1 V1.2.1 提交成功详情页

本次实现范围：

1. 客户提交需求成功后，从 `/submit` 跳转到 `/submit-success?orderNo=订单号`。
2. 提交成功页展示订单号、任务类型、联系方式、截止时间、提交时间和当前状态。
3. 成功页提醒客户保存订单号，并提供继续提交新需求入口。
4. 成功页只读取 URL 与 `sessionStorage` 中的本次提交摘要，不新增客户订单查询接口。

V1.2 开发注意事项：

1. 当前客户侧没有登录体系，客户查询需要先设计查询凭证或订单查询规则。
2. 客户可见备注必须与内部备注分开，不能直接暴露 `internal_note`。
3. 客户补充资料会影响文件表设计或新增表设计，必须先更新数据库文档。

### 5.2 V1.2.2 客户订单查询

本次实现范围：

1. 新增 `/order-query` 和 `/order-query.html` 客户订单查询页面。
2. 新增 `POST /api/customer/orders/query` 客户侧只读查询接口。
3. 查询必须同时校验订单号和提交时填写的联系方式，不支持只凭订单号查询。
4. 查询成功仅返回订单号、任务类型、联系方式、截止时间、提交时间、当前状态、需求摘要和上传文件数量。
5. 查询失败统一提示，不区分订单不存在还是联系方式不匹配。
6. 提交页和提交成功页增加查询入口。

V1.2.2 当前状态：功能已实现，待测试验收；不要标记为已验收通过。

## 6. V1.3 文件管理增强

建议在客户体验增强后，继续完善文件能力：

1. 图片预览。
2. PDF 预览。
3. 文件删除。
4. 补充文件管理。
5. 文件分类。

V1.3 开发注意事项：

1. 文件预览必须继续保留下载功能。
2. 文件删除需要同时处理数据库记录和磁盘文件。
3. 删除动作需要管理员权限保护，并考虑误删风险。
4. 文件分类可能需要新增字段，必须先更新 `DB_SCHEMA.md`。

## 7. V1.4 统计与导出

建议在后台列表和文件能力稳定后，增加统计和导出：

1. 今日订单数。
2. 本周订单数。
3. 未处理订单统计。
4. 即将截止订单统计。
5. CSV 或 Excel 导出。

V1.4 开发注意事项：

1. 导出字段必须与隐私和安全要求一致。
2. 导出接口必须要求管理员登录。
3. 统计口径需要写入文档，特别是“今日”和“本周”的时区规则。

## 8. V2.0 正式上线准备

正式上线前建议完成：

1. 管理员密码加密。
2. 环境变量完善。
3. 数据库备份。
4. 文件备份。
5. 云服务器部署。
6. 域名绑定。
7. HTTPS。
8. 日志管理。
9. 安全检查。

V2.0 开发注意事项：

1. 当前管理员密码为明文配置，不适合生产环境。
2. 生产环境必须更换 `SESSION_SECRET`。
3. 生产环境必须设计数据库和上传文件备份策略。
4. 上传文件需要更严格的安全检查。
5. 部署前必须重新跑完整测试清单。

## 9. 当前阶段暂不开发

当前阶段不要做：

1. 在线支付。
2. 聊天系统。
3. 客户注册登录。
4. 多管理员复杂权限。
5. AI 自动处理需求。

这些功能会显著增加产品复杂度、数据结构和安全边界。当前阶段应优先保证原有功能稳定，并围绕后台管理效率做小步迭代。

## 10. 后续开发会话工作规则

每个后续开发会话开始前应先阅读：

1. `PRODUCT_REQUIREMENTS.md`
2. `API_CONTRACT.md`
3. `DB_SCHEMA.md`
4. `DEV_PLAN.md`
5. `TEST_CHECKLIST.md`

开发前需要确认：

1. 本次功能属于哪个版本规划。
2. 是否需要改接口。
3. 是否需要改数据库。
4. 是否会影响旧功能。
5. 需要执行哪些测试。

开发完成后需要确认：

1. 文档是否同步更新。
2. 原有客户提交流程是否可用。
3. 原有后台登录和管理流程是否可用。
4. 上传和下载是否可用。
5. 数据库初始化是否正常。
